# API contract before Prisma integration

This records the behavior of the existing Express API before any service,
controller, or route changes. It is based on the source, README, and
`postman/library-book-api.postman_collection.json`. Book data is currently
stored in memory; adding the Prisma schema does not change this API behavior.

## Book shape

| Field | Type | Optional in response? | Behavior |
| --- | --- | --- | --- |
| `id` | string | No | Generated by `node:crypto` `randomUUID()` (UUID string); clients do not provide it. |
| `title` | string | No | Required on create; trimmed and must contain at least one character. |
| `author` | string | No | Required on create; trimmed and must contain at least one character. |
| `genre` | string | No | Required on create; trimmed and must contain at least one character. |
| `available` | boolean | No | Optional on create and defaults to `true`; if supplied it must be a boolean. |

`id` is the unique identifier. There are no ISBN or timestamp fields, no
additional field is treated as unique by the API, and there is no conflict
response. The service uses an in-memory array, so books are lost when the
server restarts.

## Endpoints

### `GET /health`

- **Success:** `200`, JSON `{ "status": "ok" }`.
- **Request validation:** None.

### `GET /api/books`

- **Success:** `200`, JSON array of Book objects; the initial response is `[]`.
- **Request validation:** None.

### `GET /api/books/:id`

- **Success:** `200`, JSON Book object.
- **Not found:** `404`, JSON `{ "error": { "message": "Book not found" } }`.
- **Request validation:** `id` is accepted as a string path parameter without
  format validation. Lookup compares it exactly to the stored ID.

### `POST /api/books`

- **Request body:** JSON object with required `title`, `author`, and `genre`
  strings and optional `available` boolean.
- **Validation:** `title`, `author`, and `genre` are trimmed strings with
  minimum length 1 after trimming. `available`, when supplied, must be a
  boolean; when omitted it defaults to `true`. Zod's object schema strips
  unrecognized keys.
- **Success:** `201`, JSON of the created Book including its generated UUID
  `id`.
- **Invalid book data:** `400`, JSON
  `{ "error": { "message": "Invalid book data" } }`.
- **Malformed JSON:** `400`, JSON
  `{ "error": { "message": "Invalid JSON" } }`.

### `PATCH /api/books/:id`

- **Request body:** JSON object containing any subset of `title`, `author`,
  `genre`, and `available`; at least one recognized field must remain after
  parsing. Unknown keys are stripped, so an empty object or an object with
  only unknown keys is invalid.
- **Validation:** Supplied `title`, `author`, and `genre` values are trimmed
  strings with minimum length 1; `available`, if supplied, must be a boolean.
  Fields may be omitted, but `null` is invalid.
- **Success:** `200`, JSON of the complete updated Book.
- **Invalid book data:** `400`, JSON
  `{ "error": { "message": "Invalid book data" } }`.
- **Missing book:** `404`, JSON
  `{ "error": { "message": "Book not found" } }`.
- **Malformed JSON:** `400`, JSON
  `{ "error": { "message": "Invalid JSON" } }`.
- **ID handling:** Same exact-string lookup and no format validation as GET.

### `DELETE /api/books/:id`

- **Success:** `204`, no response body.
- **Missing book:** `404`, JSON
  `{ "error": { "message": "Book not found" } }`.
- **ID handling:** Same exact-string lookup and no format validation as GET.

## Error behavior

Errors passed to the Express error handler use JSON shape
`{ "error": { "message": "<message>" } }`. The handler maps malformed JSON to
`400` / `"Invalid JSON"`, `BadRequestError` to `400` using its message, and
`NotFoundError` to `404` using its message. Other errors become `500` /
`"Internal Server Error"`. The existing API does not produce `409` responses.
Unmatched paths or methods do not reach this error handler and use Express's
default `404` response.

The Postman collection asserts the main success statuses (`200`, `201`, and
`204`), missing/deleted-book `404`, and invalid-input/malformed-JSON `400`.
Its create test also checks that the returned `id` is a string and saves it
for subsequent requests.
